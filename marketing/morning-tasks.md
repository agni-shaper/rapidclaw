       📝 Suggested post (adapt before publishing) — angle: token refresh patterns in RN — the single-flight interceptor
       "Spent a few hours this week debugging an auth-refresh loop in a React Native app and the fix is worth sharing.

The pattern most tutorials show — refresh on 401 inside your axios/fetch interceptor — quietly breaks the moment three parallel API calls fire at app launch. All three get a 401, all three trigger a refresh, two of the refreshes race and one wins with an already-rotated token.

The fix is a single-flight pattern: stash the in-flight refresh promise on a module-level variable, and let every concurrent 401 await the same promise. ~20 lines.

For anyone shipping RN auth: test it with three deliberately-stale calls fired in Promise.all on app cold start. If it doesn't survive that, it won't survive prod."
