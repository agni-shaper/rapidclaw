       📝 Suggested post (adapt before publishing) — angle: Engineering depth: refresh-token flow in React Native with Expo SecureStore
       "Three footguns I keep hitting in React Native auth refresh-token flows, posting so you don't have to:

1. SecureStore on Android is backed by EncryptedSharedPreferences, which silently fails on devices without a hardware-backed keystore. ~3% of mid-tier Android devices in India. Fall back to AsyncStorage + a re-auth prompt, not a crash.

2. If you refresh on every app foreground, you'll burn your refresh-token rotation budget on iOS users who background-foreground the app 40+ times a day. Debounce to once per 4 hours unless the access token is actually expired.

3. Two screens hitting an expired token at the same time will both try to refresh and one will invalidate the other. Single-flight the refresh with a Promise cache. This bites every team eventually.

None of this is in the official Expo docs in one place. Writing it up at rapidnative.com soon."

       "Watched 50 user-test sessions for a React Native app last quarter and 14 of them dropped off at login. Not at sign-up, at login.

The pattern: users who had registered weeks earlier could not remember if they'd used Google, email, or Apple. The 'Continue with X' choice page is friendly the first time and hostile every time after.

What helped: surface the last-used method with a visual hint (a faded Google logo on the button they used last time), keep all three options visible but de-emphasize the rest. Login completion went from 71% to 89% in two weeks.

The lesson I keep relearning: auth is not a form, it's a memory game. Design for the second login, not the first."

       📝 Suggested post (adapt before publishing) — angle: Design angle: the empty, loading, and error states of an auth flow are the auth flow
       "Most React Native auth designs I see specify the happy-path login screen and one error toast. Then real users meet:

• 4G to 2G mid-OAuth (loading state with no progress signal)
• Captive-portal WiFi (deep-link returns to wrong screen)
• Biometric prompt cancelled (silent fallback or hard fail?)
• Account exists but signed up with Google, user tries email (no recovery path)
• Email verification expired (which screen do they land on?)

Designing these five states upfront catches more support tickets than any visual polish on the primary screen. We ship every auth flow at rapidnative.com with a Figma frame per failure state — it forces engineering to handle each one explicitly instead of defaulting to a generic 'Something went wrong'.

Auth UX is the only part of the app where the design system is mostly about negative space."
